# Проверка игры через Engine Control

Это обязательное правило проекта Echo Front.

## Единственный допустимый способ проверки

**Вся игровая механика проверяется только через Engine Control.**

Engine Control является единственным источником достоверной проверки поведения игры. Для выполнения конкретного сценария используется Engine Command при включённом Engine Control. Engine Command должен запускать настоящий Worker и обращаться к настоящему игровому runtime через `/api/engine-command`.

Нельзя считать игровую механику проверенной по unit-тесту, integration-тесту, отдельному Node.js-скрипту, mock/stub реализации, ручному пересчёту координат или любой параллельной модели игры.

## Физика

Если проверка касается движения, столкновений, стен, дверей, лестниц, зданий, земли, транспорта, парашюта, попаданий, видимости, расстояний, ray cast, shape cast, контактов, скорости или положения объектов, результат должен быть получен из настоящего мира Rapier, используемого запущенной игрой.

Engine Control не должен подменять Rapier собственной моделью. Он управляет и наблюдает настоящий runtime. Используются те же rigid body, collider, physics queries, игровые плагины и состояние матча, что и у реального игрока.

## Как проверять изменение

1. Включить Engine Control.
2. Подготовить нужный реальный сценарий для Engine Command.
3. Запустить настоящий Worker и настоящий игровой runtime.
4. Передать действие через `/api/engine-command`.
5. Получить состояние, observation frames, журнал и другую диагностику из реально работающего движка.
6. Делать вывод о работоспособности механики только по этому результату.

Игровые runtime-пресеты и специальные игровые сцены разрешены, если они запускаются настоящим движком через Engine Control. Они не должны содержать отдельную копию игровой физики или логики.

## Запрещено

- Создавать или возвращать каталог `tests/` для проверки игровой механики.
- Добавлять `*.test.*` и аналогичную параллельную тестовую систему.
- Возвращать `npm test` как способ подтверждения работоспособности игры.
- Проверять игровую механику отдельными smoke-скриптами вне Engine Control.
- Подменять Rapier mock/stub объектами.
- Дублировать столкновения, навигацию, видимость, движение или другие игровые правила только ради теста.
- Создавать отдельный CI workflow, который объявляет игровую механику рабочей без запуска сценария через Engine Control.

## Что не является проверкой игровой механики

Сборка Worker, `wrangler deploy --dry-run`, проверка запуска процесса, health endpoint и проверка доступности WebSocket могут использоваться как инфраструктурная диагностика. Они отвечают только на вопрос, запускается ли инфраструктура, и не дают права утверждать, что конкретная игровая механика работает.

## Источник истины

Если результат Engine Control над реальным runtime расходится с расчётом, старым тестом, документацией или предположением разработчика, источником истины является результат Engine Control над настоящей игрой.

Для физической механики окончательным источником состояния является реальный мир Rapier внутри этого runtime.
